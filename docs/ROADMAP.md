# 首阶段执行计划

2026-10-29。每周 10 小时以上；以下为初学者有效投入估算，含阅读、亲手操作和调试，不含下载排队。先按每周 10 小时排，更多时间作为缓冲。每次以一个验收单元推进，不按日历强行完成。

## Phase 0 · 建立可运行、可构建的工程

| 任务 / 目标 | 学习内容 | 预计工作量 | 可交付成果 | 验收方法 | 完成标准 |
| --- | --- | --- | --- | --- | --- |
| P0-01 检查环境并建立仓库 | 引擎、IDE、运行库与 SDK 的区别；Git 工作区 | 1–2 小时 | 环境记录、忽略规则、协作规则、本地基线 | 检查实际命令输出、Git 状态和忽略规则 | 不虚构已安装工具；缓存忽略、必要资源可跟踪 |
| P0-02 安装并创建官方 2D 工程 | Hub 与 Editor 的职责；项目三大目录 | 1–2 小时，下载另计 | UnityProject、实际版本与包锁文件 | 用相同 Editor 打开；检查 Console | 导入结束无红色错误；版本已记录 |
| P0-03 制作 Bootstrap 测试场景 | Scene、GameObject、Component、Transform、正交相机、Play | 1–2 小时 | 保存的场景、可见占位方块及 .meta | Play/Stop、关闭重开场景 | 方块可见；退出 Play 后内容保留；无红错 |
| P0-04 验证脚本开发与 Git | MonoBehaviour 生命周期、序列化、补全、断点、diff | 1–2 小时 | 一个最小场景探针脚本、必要 IDE 配置、初始化提交 | 编译；断点命中；检查 staged diff；重开工程 | 编译和断点成功；只提交必要源文件，缓存不入库 |
| P0-05 第一次 Windows 构建 | Scene List、构建与编辑器运行区别、构建目录 | 1–2 小时 | 本地 Windows Development Build、验证记录 | 启动独立 exe，退出后重启；检查 Git | 独立进程显示测试场景；无阻断错误；构建不入库 |

估算合计 5–10 小时有效投入。Phase 0 门槛：P0-01 至 05 均有实际证据；只生成代码或文档不算完成。

## Phase 1 · 3—5 分钟占位内容原型

进入条件：Phase 0 通过。以下交互与剧情仅是技术占位，机制及正式故事待共同讨论。3—5 分钟是试玩目标，须用实际试玩计时验证。

| 任务 / 目标 | 学习内容 | 预计工作量 | 可交付成果 | 验收方法 | 完成标准 |
| --- | --- | --- | --- | --- | --- |
| P1-01 主菜单进入场景 | UGUI、按钮事件、场景加载、Input System UI 模块 | 2–3 小时 | 开始按钮、原型场景、返回菜单路径 | 菜单→场景→菜单往返 3 次；检查 Console | 每次能进入；没有重复事件和缺失引用 |
| P1-02 显示并推进对话 | 类与字段、列表、索引边界、TMP 字体 | 3–4 小时 | 线性占位对话与下一句按钮 | 从第一句到结束；连续快速点击；检查中文 | 顺序正确、不越界、不乱码；结束状态明确 |
| P1-03 点击场景对象触发对话 | 输入与 UI 遮挡、坐标/射线、事件入口 | 3–4 小时 | 一个可交互物体及反馈 | 点击物体、空白、覆盖它的 UI；触控适配暂后置 | 仅目标命中触发；UI 点击不误触场景；无重复启动 |
| P1-04 两个选择产生不同结果 | 分支条件、节点 ID、数据与显示分离 | 3–5 小时 | 两个选择、两个结果；小规模数据配置 | 分别走通两个分支，检查目标有效性 | 选择影响可见结果；无死路；按钮不重复触发 |
| P1-05 一键重玩与状态重置 | 状态归属、初始值、对象生命周期 | 2–3 小时 | 回菜单或重玩按钮 | A 结果→重玩→B 结果，重复 3 次 | 无上轮状态残留；无需删除文件即可重玩 |
| P1-06 有意义的分支测试 | Arrange/Act/Assert、纯逻辑与 Unity 表现分离 | 2–3 小时 | 使用实际兼容 Test Framework 的小组测试 | 运行分支及重置测试；故意破坏条件确认能发现错误 | 两条分支及重置受覆盖；测试实际通过 |
| P1-07 打包试玩并复盘 | 缺陷记录、计时、可用性观察、技术讲解 | 3–4 小时 | Windows 原型、手测记录、当前流程图与学习笔记 | 独立 exe 走完两结果；找一位首次接触者试玩 | 约 3—5 分钟完整闭环；阻断问题清零；记录不理解之处 |

估算合计 18–26 小时，按 10 小时/周约 2–3 周，另留修复时间。这是工时预算，不是交付日期承诺。第一版用流程重置满足“基础存档或流程重置”；磁盘存档在确有继续游戏需求时加入。

当前验收：P1-01 已于 2026-10-29 完成编辑器和 Windows 本机菜单闭环。P1-02 三句英文对话及静态 UI 已获用户编辑器运行确认，保存引用正确；Noto 中文字体已下载并登记，TMP 字体创建、中文显示和带对话的独立构建仍待验收。

## 技术取舍与后续门槛

- 已采用 Unity 6.6 的 Universal 2D 模板（URP）：用户已创建并打开工程；继续使用模板的 2D Renderer，不额外搭建渲染框架。
- 用户已选择 ScriptableObject 保存少量对话文本；场景组件保存当前进度。暂不引入剧情插件、全局服务框架和复杂编辑器。
- 暂不制作正式 AI 美术、不采购素材、不决定售价；原型阶段使用标记清晰的几何占位。
- Phase 2：一个 15—20 分钟章节，加入经确认的特色交互、统一美术音频、设置和存档；真实玩家反馈是扩充内容的必要门槛。
- Phase 3：根据切片反馈、预算与开发能力决定商业内容规模，再逐项增加本地化、辅助功能、成就和优化。
- Phase 4：届时查最新官方 Steamworks 与适用发行要求，准备商店、宣传、构建和版权记录。公开推送、发布、付费先获确认。
- Phase 5：Windows 版本稳定后，按反馈评估移动适配。
