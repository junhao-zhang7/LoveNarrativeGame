# 第一幕：练习本上的食堂小道

2026-11-02。作者提供《第一幕互动设计.txt》并明确选择直接接入游戏。互动不改变换座剧情：玩家陪凌赫计划午饭的小道，刚讲出后半句就被班主任打断。不是逃避老师的潜行挑战，也没有倒计时或失败结局。

## 剧情顺序

“昨天到我们就剩汤了。” → 凌赫“我发现一条小道。” → 地图互动 → 成功后“从后面绕——” → “他的手指刚划到纸边，身后传来声音。” → 班主任“绕哪儿去？” → 原有换座和午饭对白。老师出现画面在互动之后，不能在绘图前或玩家走错路时提前进入。

第一幕从18段调整为20段，五幕共103段，图片仍23张。地图是独立UI节点，不新增故事卡；完成后沿用原来的四张第一幕画面。后面的第五幕520互动保留。

## 地图与操作

校园草图画在练习本纸张风格界面，用原生纸边、笔线、地点纸片和蓝色路线绘制，清晰适配既有1920×1080界面。不下载外部地图，不使用运行时AI，也不引入3D、NavMesh或自由校园移动。

起点自动选中教学楼后门。玩家点击相连地点，画出通往食堂后门的路线，再点“就走这条”。不相连的跳跃不会加入路线；点击已画过的地点会撤回到那里；也可用“撤回一步”“重新画”。走远路的反馈是同桌自然提醒，未完成则提示先连到终点，均不推进剧情。最短路线通过后收起地图，淡入TeacherArrives并接“从后面绕——”。空格或全局Enter不能跳过地图。

【原创补充，可替换】教学楼背面、操场、楼后转角、花坛缺口、小广场和食堂前后门的校园相对布局及距离是临时演出设计，不是作者已确定的校舍实景或尺度。图上数字是示意距离，不是真实米数。重试反馈“同桌：还得绕这么一圈？看看楼后面能不能少走一点。”也是补写，不增加新的故事分支。没有把这些布局写回作者故事大纲或教室空间基准。

| 路段 | 示意距离 |
| --- | --- |
| 教学楼后门—操场边—食堂正门—食堂后门 | 90+200+80=370 |
| 教学楼后门—楼后转角—花坛缺口—食堂后门 | 40+80+40=160，最短 |
| 教学楼后门—楼后转角—小广场—食堂正门—食堂后门 | 40+80+100+80=300 |

另有小广场—花坛缺口连接，允许另一条绕行。实际判定取图中所有简单路线的最短距离，不是只检查玩家有没有点到某个地点。首版采用逐点点击连线；拖动画笔没有实现，避免把普通阅读点击误识别成自由画线。

## 实现与存档

StoryRouteState保存相邻路段、当前路径、距离和成功状态。短路判定使用小规模加权图最短距离；编辑器检查另穷举所有简单路线，独立核对唯一最短长度160。StoryRouteInput是StoryScreen的partial组成，复用既有纸边/字体/按钮，显示路线和重试反馈。requiresRoute与数学输入互斥；暂停期间不接收路线修改。

RearRowStoryDraft只升级与旧18段完全一致的资源，保留GUID，遇到用户自改稿不自动覆盖。新第一幕段落有稳定ID。内容版本升至3，旧第一幕第9段及之后的书签返回“我发现一条小道”处；已有章节完成/解锁记录不清除。新版退出时保留互动节点，未完成路线再进时从起点重画；已完成并推进后的书签不会强迫重做。

## 验证与作者测试

独立C#编译通过（既有CS1701提示）；实际执行路线相邻、非法跳跃、长路线重试、撤回、回点、重置、重复提交、重玩及穷举最短路径检查通过。构建前另检查20段资源、唯一地图节点、老师出场顺序和稳定ID。Unity实际导入/编译/构建结果见PROGRESS最新记录。没有代做Play或独立游戏操作测试。

1. 新版进入第一幕，读到“我发现一条小道。”后再继续，应出现纸张校园图，没有老师；按空格不能跳过。
2. 点“操场边 → 食堂正门 → 食堂后门”，再点“就走这条”，应提示绕路，仍在地图。试撤回和重画，不相连地点不应加入路径。
3. 正确路线：从自动选中的教学楼后门，点“楼后转角 → 花坛缺口 → 食堂后门 → 就走这条”。应收起地图，接“从后面绕——”和老师打断，而非回目录或跳到下课。
4. 未完成时退出重启，续读应仍在地图但路线从起点重画；成功后在老师打断时退出重启，应继续原对白，不重复弹图。已有解锁保留。
5. 检查地点、距离、路线线条、提示及按钮不重叠；Escape暂停时不应改动路径。第一幕结束后仍直接进入第二幕，之后第五幕答案输入照常。

学习点：路径显示与判定分开；到达终点不等于最短；剧情只在明确成功后推进。练习：分别走370和160的路线观察反馈。面试问题：为什么要把地图状态写成纯C#，并用穷举来核对最短路径算法？
