# 横向章节目录与本机续读

2026-11-02。入口：开始游戏 →《旁边的位置》故事卡 → 章节目录 → 章节或“继续阅读”。一张故事卡仍代表整部故事；目录节点对应已制作的五幕，不把章节变成独立故事，也不展示未制作章节的可玩入口。

## 行为

- 初次只有第一幕可以进入。锁定节点不显示剧情缩略图、不可点击进入；完成前一幕后依次开放。
- 每幕最后一句完全显示后，再点一次继续，才标记完成并自动淡入相邻下一幕；仅打开章节或看到最后一句不会提前解锁。解锁与下一幕第一段书签同步保存。只在当前最后已制作章节结束时返回目录；读到一半仍可手动回目录。
- 每次进入章节、推进到新段落和完成章节时保存。中途退出、返回主菜单、关闭程序后，选择同一故事的“继续阅读”可回到该幕该段开头；不记录打字动画的字符位置。
- 重看旧章节不会收回已有解锁。重看某幕读完后也接相邻下一幕；不自动跳过已完成章节。返回目录时续读遵循保存的有效书签。所有现有章节完成后仍可重看；未来在末尾追加章节，读取原存档会开放新一幕。
- 只保存到当前Windows账户的本机存储，没有云存档。旧版没有阅读记录，不能追认过去的通关，第一次使用从第一幕开始。不清理任何设置或用户存档，不提供一键全解锁。

## 实现与边界

StoryReadingState是纯C#状态：已完成章节ID集合和当前章节/段落书签分别保存，以稳定的storyId匹配；内容增长时保留已完成记录，缺少前置章节的记录不解锁更后面的章节。异常书签限制在合法范围，未知版本按初始状态处理。

StoryScreen从整篇串读改为一次读取一个章节，并创建手绘纸张风格的横向节点、连接箭头、完成状态与续读按钮。现有五幕同屏；更多幕时支持横向拖动和左右箭头。播放中右上角和暂停页可回章节目录，目录可返回故事卡。全屏图片与半透明对白保持。

每个bookId使用独立PlayerPrefs键SchoolPrototype.Reading.V1.<bookId>，JsonUtility序列化小型记录；每次推进后显式Save，读取错误输出警告，保存失败在目录提示。没有修改操作系统设置。参考[Unity 6.6 JsonUtility官方说明](https://docs.unity.cn/6000.6/Documentation/ScriptReference/JsonUtility.html)。这不是多槽存档；若后续正式添加大量选择变量，再根据实际数据扩展存档格式。

## 验证和作者测试

独立C#编译通过（工具链既有CS1701提示）。纯状态边界检查通过，涵盖首次锁定、拒绝越级、未读完不解锁、书签恢复、顺序完成、重看不退回、全通后追加内容、异常完成记录、书签越界、未知版本、不同故事、单段章节和快照隔离。编辑器构建前另执行JSON往返检查，不写入作者的PlayerPrefs。连续衔接版本追加逐章完成及边界续读检查通过。本次未代做Play或独立游戏操作；构建结果见PROGRESS最新记录。

1. 打开新版游戏 → 开始游戏 → 故事卡。应先看到横向五幕目录，初次只有第一幕可进入，第二至第五幕锁定。
2. 进入第一幕，读几段后返回章节目录或直接退出游戏。重启后点“继续阅读”，应回到刚才那段。点锁定节点不应进入剧情。
3. 完整读完第一幕，在最后一句再点继续。应直接淡入第二幕第一段，不出现目录。手动回目录后第一幕显示已完成，第二幕解锁，第三幕仍锁定；续读接第二幕当前段。
4. 第二幕中途退出后重启检查续读；再完整重看第一幕，应直接衔接第二幕，已有解锁应保持。其他已完成章节也可重看，不需要从第一幕再读整篇。
5. 逐幕完成至第五幕后，所有已完成节点可重看；末尾不出现未制作第六幕的可玩入口。核对缩略图、中文、按钮和全屏画面，音乐持续。

学习点：解锁进度与阅读位置是两个状态；只进入章节不等于完成；稳定ID比数组下标更适合跨版本匹配。练习：读完一幕后重启观察状态，先不要删除存档。面试问题：为什么重看第一幕时不能把“已解锁最高章节”直接改成当前章节？
