# 校园故事：互动创意与制作评估 v0.1

2026-10-30 · 全部为【提案】，尚未批准或实现。配套：[故事分析](STORY_ANALYSIS_V0.1.md)、[场景与事件结构](STORY_STRUCTURE_V0.1.md)。

## 1. 核心提案：同一页，同一声铃

**P09：让两个人操作同一段相处的不同部分。** 凌赫掌握讲解的纸与笔，李晚云掌握跟随、标记和自己未完成的学习。后期，凌赫面前仍是习题，李晚云面前却是走廊中的一本书。同一声铃在两侧结束同一段时间。

辨识度来自“共同事件不变、行动职责不同、相同动作随关系改变意义”的组合。拖纸或翻书本身不算新发明；目前也没有证据宣称业界首创。值得验证的卖点是：玩家第二次亲手经历自己第一次没有看见的那部分时间。

操作不识别玩家是否真诚，不通过手速推断人格。所有影响剧情的动作须有可见语境和确认；鼠标悬停、阅读慢、使用提示不产生负面结算。重大既定事件采用明确演出，不用必输小游戏掩饰。

## 3. 重要交互规格

以下工时为单人初学者在复用基础点击 / 拖放后完成一个灰盒机制的粗估，含学习与调试，不含正式插画、音乐制作和完整内容填充；存在重叠，不能直接相加作总预算。

### IN-01：让出一块桌面

- **场景 / 目的**：A-010、A-012；把换座与补救变成身体性的行动，建立两张直角课桌的空间关系。
- **情感意义 / 可见信息**：老师已要求换座；新位置、书堆、杯子都可见。玩家不能改变被调座的既定事实。
- **操作步骤**：点击书堆，再点击新桌面宽目标区，或拖过去；固定动画发生碰杯后，点击扶杯，再完成一次收拾动作。别模拟热水伤害或要求精细擦遍全屏。
- **反馈**：书放下的闷响、凳子轻响；角色让出半步，水杯归位；镜头抬起时短暂对视。无人受伤沿原稿保持。
- **分支 / 状态**：只记录 EV-001、003 完成，摆书先后可影响一个细节动作，不产生好感分或结局条件。
- **失败 / 退出**：错放轻微回弹并显示有效区域；三秒不操作可出现提示但不自动惩罚；点击代替拖拽。退出恢复节点起点，重复点击不重复事故。
- **二周目**：不整段重做搬运；她的私人桌面整理在 B-010 显示同样物件另一侧的位置。
- **Unity / 资源**：UGUI Image、RectTransform、宽命中区、有限状态步骤；纸书杯各一张图、两帧手部、短音效。无需刚体堆叠、水模拟或骨骼动画。
- **成本 / 风险**：简单，4–8 小时。风险是把家务做得太长；单次动作完成即进入反馈，整段控制在一分钟内。

### IN-02：递出的核酸码

- **目的 / 情绪**：让玩家经历凌赫的自我表演及对方实际反应，留下“他以为自己做得很好”的具体记忆。
- **可见信息**：一周目明确显示他先拿到了码并故意等待；不靠二周目突然揭露。二周目只给她排队时知道的内容。
- **操作步骤**：点击桌上纸卡收好 → 既定排队演出 → 到交付节点点击纸卡、交到对方手边。交付之前不显示能提前归还的假按钮。
- **反馈**：短暂摆姿势；她急着拿码并离开，感谢保持原稿；现场人声持续，不出现英雄胜利音效。
- **分支 / 状态**：EV-004 固定为迟交；记录交付完成。该段主要是参与演出，不冒充决定命运的玩法。
- **失败 / 退出**：可跳演出但保留已发生事实；无倒计时，无让她当众受罚的操作失败；从交付前检查点恢复。
- **二周目**：操作自己的书和口袋，发现缺码，再接过；她不会自动知道他故意晚给。无需强制长时间排队。
- **Unity / 资源**：同一点击 / 拖放模板、纸卡 Image、两处背景裁切、手势与三种面部反馈；用虚构无有效个人信息的纸卡图案。
- **成本 / 风险**：简单，3–6 小时；主要风险是演出奖励操纵。若试玩只觉得男主“帅”，应调整镜头反馈而非用说教旁白定罪。

### IN-03：同一页的两种进度（核心）

- **目的 / 情绪**：让玩家实际做“让另一个人跟上”这件事。解题熟练与理解对方是两种不同能力。
- **可见信息**：习题和原稿正确解法被拆成三步：端点与顶点 → m²+n² → 合并得 520。玩家可以查看完整解法，数学知识不构成门槛。李晚云卡住哪一步通过可见的停笔 / 指向表达，不要求猜脸色。
- **男主操作**：选要说明的一步 → 将纸推至两人中间（约 90 度转向，与直角课桌对应）→ 在已标记的式子处点击示意 → 把笔放到交接区，或选择先展示完整思路再交接。两种方法都能推进，不存在拖到隐藏像素才算体贴。
- **女主操作**：同一讲解按一周目记录播放；她把书签放到自己想复核的那一步，跟着补上预设算式。她可查看注释、暂停、换阅读顺序；已经发生的提问与男主回应直接重放。不会为私人标记生成一段一周目没有说过的新公共对白。
- **反馈**：纸旋转、铅笔停顿、手指留在某式；直接讲完的反馈是全貌清楚但需要再回看，分步交接的反馈是参与更多但节奏更慢。男主画面不出现“她理解度 70%”。轻微音乐在交流稳定时进入，不作为正确操作奖励。
- **分支 / 状态**：`studyExchangeTrace` 记录选择了哪种讲解顺序、何时交笔、已公开的提问；EV-005 始终完成，饭约仍成立。后续只能引用实际说过的步骤。私人书签位置只存 B 状态。
- **完成 / 错误 / 退出**：三步呈现且笔完成一次交接后结束；放错位置回弹，显示可用区；“看完整讲解”可辅助完成，无关系惩罚。退出回到本步骤起点，不能重复提交 EV-005。正文阅读不消耗剧情时间。
- **二周目价值**：看见一份流畅讲解仍可能有自己没来得及接上的地方；也体验到她自行理解后的满足，不把她设计成永远听不懂。
- **Unity / 资源**：UGUI 纸页与步骤层、拖放接口、预设高亮、局部旋转；一个步骤驱动器管理“查看—示意—交接—确认”；有限语义动作列表驱动回放。需桌面图 1、习题页 1、笔 / 书签各 1、手势 3–4 个、纸笔音效；不用手写识别、实时绘线判分或通用数学求解器。
- **成本 / 风险**：中等，14–24 小时；难点是角色权限和回放一致性，不是拖拽本身。若试玩者只在搬卡片，应减少步骤、增强角色跟随反馈；不能靠增加谜题难度补救。

### IN-04：纸张的两面

- **目的 / 情绪**：纸条表达“已经递出、尚不知道回应”，照片表达“将共同瞬间放进自己的生活”。两个短动作复用纸张呈现，非两个大型小游戏。
- **可见信息 / 步骤**：A-021 可见原稿化学式，沿明显折线点击一次折起，再交出；B-020 点击展开、按既定宿舍反应演出。B-021 将合照拖到日记宽区域，写字用预设笔迹动画呈现原稿句子，不识别手写。
- **反馈**：纸声、短暂收手；宿舍声音与雪中快门分别有温度；不把暗号渲染为玩家必须解开的谜。
- **分支 / 状态**：EV-007、008 既定；贴的位置只有视觉差异。实体合照持有人是李晚云，男主视角不凭空获得道具。
- **失败 / 退出**：宽吸附、点击放置替代；可跳笔迹动画；错误拖出回原位。半途退出不丢图、不重复产生副本。
- **二周目**：男主完成送出，女主完成打开与留存；同一物件承担不同动作，不能只换立绘重演。
- **Unity / 资源**：Image 翻面 / 两帧折纸、RectTransform 吸附、预制照片、日记页、笔迹遮罩或逐段显现。合照是预绘 2D 图，不做截图系统。
- **成本 / 风险**：简单至中等，6–12 小时；正式合照插画另计。雪用少量循环粒子或序列帧，不让玩家甩鼠标制造误伤。

### IN-05：写得下，未必发得出

- **目的 / 情绪**：把断联的犹豫变成手里未完成的动作，同时尊重原稿此后未联系的事实。
- **可见信息**：已有聊天和母亲语音来自原稿。玩家只知道凌赫担心她挨骂，不直接知道她此刻发生什么。
- **操作步骤**：在私人草稿区选择一两个关注点（学科 / 问候 / 解释），预览自然语句片段；可收起或删去草稿。母亲语音之后的既定断联段不提供能实际发送的按钮；显示这是未发送草稿，不假装网络故障强行拦截。
- **反馈**：输入区文字出现、光标停留、手机放下；音效朴素。不能用“正在输入”伪造对方此刻的事实。
- **分支 / 状态**：私人草稿类型改变男主的短反应，不进入女主可见消息；EV-010 的断联保持。正式往来片段按已发生事件记录。
- **失败 / 退出**：不限时，点击可撤销；不自由输入；关闭界面前确认是否保留私人草稿，暂停不自动发送。
- **二周目**：重点是她在自己的学习与有限联系条件中怎么安排，不把男主草稿透露给她。已发消息只读，私人小安排不改变消息时间线。
- **Unity / 资源**：滚动消息列表、TMP、预设片段按钮、草稿状态；手机框 1、背景色变体，不复刻整套真实应用。
- **成本 / 风险**：中等，8–16 小时。主要风险是拼句变正确答案；所有草稿都应是可信表达，不能用措辞解锁“免受家长限制”。

### IN-06：自己的名字，别人的条件

- **目的 / 情绪**：让改科是看清后承担的决定，不是一个看起来能随时撤回的菜单点击。
- **可见信息**：原史政地表、他的兴趣、老师原条件及已问过的替代方案。仅展现故事确认的成绩信息，不编全国就业结论。
- **操作步骤**：翻看原表 → 点击兴趣、同班、家长条件三个话题询问（不是拼最佳顺序）→ 查看变更后科目 → 明确确认提交。主线改科是按作者路线经历；H 路线批准并完整制作后，才在此开放真正保留史政地的提交。
- **反馈**：新表放到旧表旁、笔停在签名位置；办公室环境声继续。不要让历史文字自动褪色、把理科涂黑，替玩家判好坏。
- **分支 / 状态**：EV-013、014；记录实际询问过的内容、路线和最终提交。原初填表事实不删除；改科记录为后续事件。
- **失败 / 退出**：提交前可返回检查；退出从未提交状态恢复。无长按越久越爱对方、无不可读倒计时；防双击重复提交。
- **二周目**：她处理自己的表和听见的改科结果，不进入男主办公室替他改答案；自己的学科心理须作者确认后配置。
- **Unity / 资源**：表格 Image、TMP 文字、选择预览、确认弹层、CanvasGroup；2 张表、笔与桌面、教师局部表情。
- **成本 / 风险**：中等，8–14 小时；主要风险是伪装自由选择。内容前提 P05 未确认前，不能制作成正式关卡。

### IN-07：同一声铃的两侧（核心）

- **目的 / 情绪**：让玩家分别承担“结束手头的事”与“安排空出来的时间”。距离只有一间教室，接近却不再自动发生。
- **可见信息**：前一场已明确见面约定、地点、课间结束的铃。首次原设失约是演出，不要求玩家靠发现隐藏时钟避免。
- **男主操作**：失约事件已发生后，从习题中标出下次继续的位置 → 收笔 → 选择先承认失约事实或先说明讲题缘由 → 按已知约定走到门口。后续修复场次可明确提前收尾或说明改约，不能承诺了又由脚本偷偷判没做。
- **女主操作**：书在手里、对面窗户可见；点击读一小段、放书签、抬头看一次，再选择暂收书或在可用时段继续读。关键公共时点按快照发生；已被一周目看见的位置不能改。她可以完成自己的阅读，不需要把全部等待用来凝视男主。
- **时间推进**：使用 3–4 个叙事节拍，玩家确认完成当前小动作后才推进下一拍。停下读字、打开设置不让铃声偷偷越过。公共事件演出按相同顺序重放，不按玩家鼠标耗时重放；无需真实等十分钟。
- **反馈**：男主侧纸笔声近，走廊声稍远；女主侧翻书声与脚步近，教室讲题只能听清角色合理听见的片段。铃声是同一段素材、同一事件位置。抬头、合书、离开用短动作，不强制黑白滤镜。
- **分支 / 状态**：EV-016、018–020；约定与失约是否发生取自剧情事实，后续说明和修复有实际差异；私人阅读标记只属于 B。一次主动说明应减少相应误解，但不自动解决所有家校压力。
- **失败 / 退出**：明确标注可操作物件；不操作提示一次，提供自动完成生活动作；没有耐心量表。退出恢复到节拍边界；重复看窗户不追加伤害值。
- **二周目价值**：玩家认得同一纸页和铃，却第一次要决定怎样过那段空出的时间。她的书页前进也意味着生活没有完全暂停。
- **Unity / 资源**：有限节拍控制、动作事件表、双视角表现映射；教室局部和走廊 2 个构图、同一钟 / 铃资源、书页 / 书签、角色 3–4 姿势；只做画面层级与音量变化，不模拟完整校园寻路。
- **成本 / 风险**：中高，18–30 小时；主要是双视角权限、加载恢复、节拍跳过的一致性。若只做一侧可省代码，但会损失本项目的核心体验，优先减美术而不是删另一侧。

### IN-08：能承诺的范围

- **目的 / 情绪**：把最后的分歧落在可实践的安排，让人物认真尝试，而不是点击“我还爱你”即可解决。
- **可见信息**：已经确认的课表、联系方式限制和双方表达过的需要。未知限制不能临时出现堵死玩家方案。
- **操作步骤**：展开一个具体方案（减少见面 / 固定联系窗口 / 有期限暂停）→ 将自己的可行时段放在对应处 → 看对方基于既定立场的回应 → 可调整或承认做不到 → 明确确认当下结论。至少一项方案曾在 CH04 有效，不让所有格子天然冲突。
- **反馈**：能够重合的格子确实重合；仍有一方不能接受时，由可理解的具体需求表达。没有“匹配度 99%”或成功音；最终收表与收书留下短停顿。
- **分支 / 状态**：EV-022、023，记录讨论与同意的实际内容、S1/S2 收束方式。本主线结束依赖已确立的角色立场；如果玩家提出双方都愿接受且可行的长期安排，就需要批准继续路线，不能假装其无效。
- **失败 / 退出**：无错误方案罚分、无拖到精确格点考验；可用列表选择代替拖放。提交前可撤回；最终节点后记录不可反改，读档回此前建立新尝试。
- **二周目**：共同谈话只读重访；操作谈话前后自己的安排与物件，不再次改公共承诺。照片可保留或收起，两者均不判“放下 / 没放下”的优劣。
- **Unity / 资源**：固定数量的方案数据、宽时段目标区、条件检查、角色反应段；复用表格和桌面模板，不写通用排课优化器。
- **成本 / 风险**：中等，10–18 小时；文学因果成本大于代码。P06 未确认前只做纸面推演；切片暂不包含结局，避免为赶演示先定人物命运。

## 4. Unity 落地边界与职责提案

已核对本项目 Unity 6000.6.7f1、Input System 1.20.1、UGUI 2.6.0，现有脚本仍是单物体触发和字符串数组对话。以下是待批准的扩展方向，不是已存在功能。

| 职责 | 做什么 / 输入输出 | 与现有工程的关系 |
| --- | --- | --- |
| 剧情数据 | 场景 ID、台词段、互动入口、事件条件与后继 | 继续优先 ScriptableObject；先加切片需要的少量字段，不立即建设通用编辑器 |
| 场景流程 | 读剧情段 → 启动交互 → 收到明确完成结果 → 进入反馈段 | 从现有 DialoguePresenter 逐步扩展；不让点击物件直接修改整条剧情 |
| 互动表现 | 管拖放、吸附、步骤、提示、动画；输出语义结果 | 不决定好感度或人生结局；同一模板复用多处纸张 |
| 事件记录 | 验证事件前提，提交一次共同事实，提供只读重放 | 与 ScriptableObject 内容资源分开；不把已玩状态写回共享资产 |
| 存档 | 保存当前节点、路线、事件快照、私人状态、版本 | 本地文件；在节点完成时保存，临时文件写完再替换并留旧备份；不承诺跨版本自动兼容 |

ScriptableObject 适合配置内容，独立 Player 的持久存档需另做；采用它并不等于已拥有存档系统。[Unity 6.6 官方说明](https://docs.unity.com/en-us/engine/6000.6/manual/scripting/get-started/fundamental-unity-types/class-scriptable-object)。

拖放使用 EventSystem 的开始 / 持续 / 结束拖拽及放置接口；本机 UGUI 2.6.0 的 EventInterfaces.cs 已核对包含对应接口。公开概念参考页标的是 UGUI 2.0，不能据此声称项目版本为 2.0。[官方事件说明](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/manual/SupportedEvents.html)。触屏由同一 UI 事件入口处理，仍需未来实际设备验证，不能因接口共用宣称已适配。

CanvasGroup 可统一控制面板透明、可交互和图形射线阻挡；遮挡与显隐一并管理，避免此前“透明层挡点击”的问题。[Unity 6.6 CanvasGroup](https://docs.unity.com/en-us/engine/6000.6/script-reference/unityengine/canvasgroup)。

存档候选为简单可序列化对象 + JsonUtility；事件列表包在对象内，不直接用裸数组作为顶层。保存时写字段数据，不序列化场景 GameObject 引用。[Unity 6.6 JsonUtility](https://docs.unity.com/en-us/engine/6000.6/script-reference/unityengine/jsonutility)。

本轮不引入 ink 或 Yarn Spinner：当前内容小，先验证双视角事件模型是否成立。若作者定稿后分支文本维护成为实际问题，再比较工具；不同时叠加两套剧情框架。声音用 AudioSource 与少量混音分组，演出先用预设动作或简短动画，不做全角色实时表演系统。

## 6. 验收与试玩问题

实现批准后，自动化重点是事实一致性：同一事件重复完成只提交一次；切换视角不能写回共同快照；跳过与正常播放得到相同必要事实；新路线不污染旧记录；保存恢复不丢承诺或重复交付。不是为每个按钮机械地写镜像测试。

手工重点：宽屏 / 16:9 下命中区正确；UI 遮挡不穿透；鼠标拖拽和点击替代结果相同；打开菜单不推进时间；跳过演出不会丢事件；反复进出、关闭 Unity 后独立 exe 加载正确；无新缺字与阻断报错。触屏尚未测试，后置单列。

邀请首次接触故事的人时，先观察而不讲解主题：

1. 他是否知道当前扮演谁、能操作什么、哪些事已发生？若认为被程序强迫按错，固定事件的呈现需改。
2. 他能否描述两人各自想要什么，而不只说“女生吃醋”？若不能，先补冲突事实，不增加旁白。
3. 女主侧是否让他理解新事，还是只觉得重播拖时长？若只是重播，删重复台词、增加她自己的实际行动。
4. 他是否认为答题 / 拖法有一个爱情标准答案？若是，检查反馈和奖励是否在暗中评分。
5. 一次没有成功沟通后，他是否能说出具体原因？若只觉得作者不让成功，说明因果或交互权限需要重做。

商用潜力目前只能提出假设：近距离校园相处、同一事件两侧操作、重复动作的情绪变化可能形成易展示的特色。宣传片可展示同一张纸旋转到另一侧、同一铃声下两种动作；不必剪分手哭泣来证明情感。未做市场对标、销量预测或商店测试，不能宣称机制已具销售优势。
